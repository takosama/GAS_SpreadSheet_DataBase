# GAS_SpreadSheet_DataBase

Google Apps Script中でSpreadsheetをDBとして扱うTypeScriptライブラリです。
`DB.ts`をApps ScriptのV8向けJavaScriptに変換して利用してください。外部サービス・Advanced Sheets API・新規権限の追加は不要です。

## 基本的な使い方

```ts
const db = new SpreadSheetDB();
db.Create("people", ["name", "active"]);
db.Insert({ name: "example", active: true });
db.Save();

const existing = new SpreadSheetDB();
if (!existing.Connect("people")) throw new Error("Sheet not found");
existing.Filter((row) => row.active === true);
const rows = existing.Result(); // 配列内の各行は辞書。JSON.stringify可能
existing.Save();
```

- 1行目のA列は採番カウンター、2行目は先頭`id`＋ユーザー列、3行目以降はデータです
- `Create(name, [])`も利用可能です。作成後は自動的に新しいDBへ接続し、列・データ・IDを初期化します
- `Connect`がfalseを返すか例外になると、以前の接続状態は破棄されます
- `Create`は開始時点で以前の接続と未保存のメモリ内変更を破棄します。引数不正やロック取得失敗でも旧DBを選択したままにはしません。残したい変更は先に正常に保存してください
- `Insert`、`Map`、`Filter`はメモリ上のデータを変更し、`Save`で反映します
- `Map`の第2引数に渡されるIDはnumberです。以前の型宣言はstringでしたが、実際にはnumberを渡していました
- `Map`と`Filter`のコールバックに渡すレコード、`Result`のレコード、Date値は内部データから分離されています。コールバックが失敗した場合、途中までの変換は反映しません。コールバック内でDBを再帰的に変更したり、外部へ副作用を起こしたりしないでください
- レコードはnullプロトタイプの辞書です。`__proto__`等も通常の列として扱えます。`hasOwnProperty`を直接呼ばず、必要なら`Object.prototype.hasOwnProperty.call`を使用してください
- `View`はタブ区切り・改行区切りです。`GetLog`は操作名と行数のみで、セルの値は含めません。ログやデータをURLのクエリに貼り付ける運用は避けてください

## 保存と競合検知

`Save`は先行する`sheet.clear()`を使いません。型・列数・行数・IDを検証し、旧領域まで空文字で埋めた矩形を1回の`setValues`で書き込みます。全件Filterした空DBや列削減も扱い、セルの書式を意図的に消去しません。

ロックを取得した上で、`Connect`または直前の正常な`Save`時点のスナップショットと現在の値を比較します。別インスタンスなどが値を変更済みなら、書込み前に拒否します。競合したインスタンスは再接続するまで変更・保存できません。接続し直して最新データを読み、必要な変更を再適用してください。単にロックを追加するだけでは、古いデータによる上書きを防げないための仕組みです。

- 文書ロックが利用できればそれを使い、なければスクリプトロックを使います。待機上限は30秒です
- 同じロックに参加しない別スクリプトや手動編集を停止するものではありません。確認と書込みの間に発生する外部の更新を完全には防げません
- スナップショットは値の変更を検知します。変更後に元の値へ戻った操作や、書式だけの変更の履歴は検知しません
- 1回の`setValues`であることを、トランザクションや原子的な保存の保証とは扱いません
- 書込み後は`flush`と読取りで値を照合します。書込み・flush・確認読取りが失敗した場合は、結果不明としてインスタンスを無効化し、追加の保存や変更を拒否します。シートの実状態を確認してから`Connect`し直してください
- 応答が失われた時点で書込みが完了している場合があります。自動再試行や自動ロールバックは、保存後の他者の更新を潰し得るため行いません。失敗時に必ず旧データへ戻る保証もありません
- 保存前の入力検証エラーやロック取得失敗では書込みを開始しません。内容を訂正するかロックの原因を解消して再実行できます
- `Create`失敗時には新規シートが残る場合があります。旧DBは選択解除されます。残ったシートを確認し、必要なら復旧してから再接続してください
- グリッドの行・列容量が不足する場合は、保存前に拒否します。シートを拡張し、再接続・再適用してください

重要なデータでは、このライブラリとは別にバックアップや復旧方法を用意してください。Apps Script本番環境での原子性やネットワーク障害時の挙動は、このリポジトリのモックテストでは実証していません。

## 入力規則と互換性の変更

安全のため、以前受け入れられた一部の入力を明確に拒否します。

- セルはstring、有限のnumber、boolean、有効なDateのみ。空欄は`""`を使い、null・undefined・配列・オブジェクト・NaN・Infinityは拒否します
- 数式として解釈され得る先頭`=`、および空白に続く`=`の文字列を、Insert/Map/Save/Connect/Createの各入力検証で拒否します。先頭アポストロフィーによるエスケープの動作には依存しません
- 既存シートに数式セルがある場合も接続・保存を拒否します。数式の計算結果を無意識に保存して元の式を失うことを防ぎます。必要な場合は、別途確認した上で値のみのDBを用意してください
- 列名は空でない重複のない文字列。先頭`id`は予約列で、ユーザー列として重複できません
- 各レコードはすべてのユーザー列を自身のプロパティとして持つ必要があります。欠損値を暗黙にundefinedとして保存しません
- データ行は列数の揃った矩形。IDは重複のない非負の安全整数で、カウンター以下でなければなりません
- 結合セル、途中の空行、不正なヘッダーやID、メタデータ行の追加データを含むシートはDBとして扱いません

数式文字列の保存が必要な用途は、この制限を解除する前に、文字列としての保存経路とGAS実環境での安全性を別途設計・検証してください。

## ローカル回帰テスト

Node.js 24以上で、依存パッケージのインストールなしで実行できます。

```sh
node --test tests/db.test.cjs
```

Node組込みの`stripTypeScriptTypes`とVM、SpreadsheetApp/LockServiceのモックを使用します。型の除去機能は実験的APIのため警告が出る場合があります。実シートやユーザーデータへ接続しません。

テスト対象は、全件削除、列縮小、Create後の状態分離、辞書のJSON化、特殊キー、コールバック失敗、Dateの分離、不正入力・数式拒否、並行インスタンスのstale更新、保存前・保存後・部分反映エラー、外部編集、flush失敗、接続失敗、ロック解放等です。

型除去はTypeScriptの型検査ではありません。別途、検証専用の環境に導入したTypeScript 7.0.2と`@types/google-apps-script` 2.0.13で、次のstrict型検査に成功しています。コンパイラと型定義はこのライブラリの実行時依存には追加していません。

同じコンパイラと型定義を利用できる環境では、次のコマンドで再現できます。Apps Script用のためDOMライブラリを含めず、`--lib ES2020`を指定します。

```sh
tsc --strict --noEmit --target ES2020 --lib ES2020 --types google-apps-script DB.ts
```
